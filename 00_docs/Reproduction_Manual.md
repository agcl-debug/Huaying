## 二、环境搭建

### 2.1 硬件要求

| 项 | 要求 | 说明 |
|---|---|---|
| **磁盘** | **≥ 1 TB 可用** | 数据 624 GB，复现过程还需中间产出 |
| **内存** | **≥ 16 GB**（推荐 32 GB） | 30 m 全域单幅约 1.3 GB，峰值约 8 GB |
| **位数** | **必须 64 位** | 栅格 22313×15265，32 位会溢出 |
| **CPU** | 4 核以上 | 12 核实测约 6 小时 |

### 2.2 软件安装

```bash
# 1. 安装 Python 3.10+（实测 3.14.7 通过）
# 2. 安装依赖
pip install -r 00_总说明/requirements.txt

# 3. 【Linux 必需】安装中文字体，否则图中中文显示为方框
sudo apt install fonts-wqy-zenhei        # 或 fonts-noto-cjk

# 4. 自检
python check_env.py
```

**不需要**：ArcGIS、MATLAB、GDAL 命令行。
**只在想用原工具重绘时需要**：OriginLab Origin（打开 `.opju`）、ArcMap（打开 `.mxd`）。

### 2.3 常见环境问题

| 报错 | 原因 | 解决 |
|---|---|---|
| `CRS not found` / `PROJ: proj_create` | PROJ 数据路径 | 设 `PROJ_LIB` 指向 `rasterio/proj_data` |
| 图中中文是方框 | 缺中文字体 | 装 `fonts-wqy-zenhei`，或改代码里的字体名 |
| `MemoryError` | 内存不足 | 关掉并行；或只跑部分阶段 `--stages 3` |
| 路径含中文报错 | 编码问题 | 设 `PYTHONIOENCODING=utf-8` |
| `FileNotFoundError: mask_300m.tif` | 数据未就位 | 确认 `03_过程数据/300m工作数据/grid/` 存在 |

## 三、执行顺序

### 3.1 全量复现

```bash
python run_all.py
```

会依序跑 10 个阶段。**每阶段可中断、可续跑**：已完成的产出会先校验有效性，有效则跳过，无效则重算。

### 3.2 只跑部分阶段

```bash
python run_all.py --stages 3,4      # 只跑阶段 3 与 4
python run_all.py --stages 6        # 只重算景观生态风险
```

### 3.3 阶段说明

| # | 阶段 | 耗时 | 产出 |
|---|---|---|---|
| 1 | 数据预处理（30 m → 300 m 聚合） | ~3 h | `03_过程数据/300m工作数据/` |
| 2 | RUSLE 侵蚀与水土保持 | ~25 min | `04_成果栅格/水土保持与侵蚀_300m/` |
| 3 | InVEST 四类服务 | ~14 min | `04_成果栅格/生态系统服务_300m/` |
| 4 | 趋势与持续性 | ~6 min | `04_成果栅格/趋势与持续性/` |
| 5 | 地理探测器 | ~90 min | 驱动机制结果 |
| 6 | 景观生态风险 | ~20 min | `04_成果栅格/景观生态风险/` |
| 7 | 生态网络 | ~15 min | `04_成果栅格/生态安全格局/` |
| 8 | ESCI | ~4 min | `04_成果栅格/ESCI/` |
| 9 | SDGs 修复路径 | ~2 min | `04_成果栅格/SDGs修复路径/` |
| 10 | 图件与表格 | ~5 min | `05_出图数据/` |

### 3.4 分阶段底层命令（脚本直接调用）

```bash
cd 06_文本/代码_校正研究
python run_corrected.py --stages 1        # 单个阶段
python run_corrected.py --stages 3,4,5    # 多个阶段
python run_corrected.py --stages 6        # 重算
```

## 七、必须知道的口径（否则结果会不一样）

**这是本研究最容易出错的地方** —— 以下选择**都会改变结论**，但**都不会报错**：

| 口径 | 必须用 | 用错的后果 |
|---|---|---|
| **二值栅格聚合** | **max** | 用众数会把道路抹平（实测 hir 从 127,343 像元降到 **3** 个），致 **生境质量趋势方向反转** |
| **DI 归一化** | 各分量**除以自身均值** | 用 min-max 得 ERI 0.006（应为 0.047） |
| **景观指数公式** | 论文原式 `C=n/A`、`N=√(n/A)·(A/A_i)` | 用其他形式位次相关只有 0.068（应 0.985） |
| **空间统计对象** | **9 km 单元** | 算在克里金插值面上会得 0.9966（应 0.5616） |
| **中心性度量** | **Conefor PC（含斑块内项）** | 用连通性下降会**完全反转**排序 |
| **MSPA 前景** | 二级分类 + **FVC≥0.3 拆草地**、排除裸地 | 用一级类会致核心区只有 1 块（应 516） |
| **Hurst** | 标准 R/S + **截断 [0,1]** | 不截断会得"正持续 100%" |
| **产水总量** | `水深(mm) × 面积(m²)/1000` | 论文口径少算 **10.11 倍** |
| **碳密度单位** | **t/ha** | 论文输出实为 t/像元，差 **11.111 倍** |

完整 21 条口径见 [`../06_文本/系统化改造/口径声明.md`](../06_文本/系统化改造/口径声明.md)。

## 八、已知的数据局限（不是复现失败）

| 局限 | 影响 |
|---|---|
| **道路栅格 2006–2012 七年为同一份文件** | 生境质量在 2006、2011 的台阶**是数据缺陷的投影，非真实生态变化** |
| **2014 年道路威胁像元异常少**（hir 2,006 vs 邻近年的 6,841/6,900） | 该年 HQ 虚高、次年回落被放大 |
| **C 因子血缘止于 `H:/真C/`** | 该输入**可复现但不可追溯**；验证套件对 RUSLE 链条只做守恒/值域检查 |
| **路网矢量缺 2001–2009、2011** | 四级道路用最近邻类别赋值 |

## 十一、代码可移植性说明（重要）

本复现包的代码已改造为**不依赖任何写死的盘符路径**。

### 11.1 路径解析机制

`run_corrected.py` 从**脚本自身位置向上**查找包根（含 `03_过程数据` 的目录），据此解析：

| 变量 | 解析结果 |
|---|---|
| `PKG_ROOT` | 复现包根目录 |
| `REPRO_ROOT` | `06_文本/`（含 `repro/` 包） |
| `GRID_DIR` | `03_过程数据/300m工作数据/grid/` |
| `MASK_300` | 同上 `/mask_300m.tif` |
| `DATA_300` | `03_过程数据/300m工作数据/` |
| `OUT_ROOT` | `06_文本/代码_校正研究/out/` |

**所以把 J 盘插到任何电脑、挂载到任何盘符，都能直接跑。**

> 若你的目录结构与本文不同（例如只复制了 `06_文本/`），
> 可在 `run_corrected.py` 顶部的 `_REPRO_CANDS` 与 `_pick()` 候选列表里手工指定。

### 11.2 `out/` 目录的设计（**重要**）

```
06_文本/代码_校正研究/out/     ← 流程的**运行产出目录**（已预置真实复制）
04_成果栅格/                    ← **参考成果**（冻结，只读）
```

**`out/` 已预置了参考成果的真实复制（1,058 MB）**，因此：

- ✅ **任何阶段都可以独立重跑**（不必从阶段 1 顺序跑）
- ✅ 重跑产生的产出写在 `out/`，**不会改动 `04_成果栅格/` 的参考成果**
- ✅ 跑完后可与 `04_成果栅格/` 逐项比对，验证复现是否成功

> ⚠ **切勿把 `04_成果栅格/` 硬链接（Hard Link）进 `out/`** ——
> 硬链接共享同一份数据，运行流程会**同时改写参考成果**。
> 本包已用真实复制规避该问题（开发过程中曾因此误改过 ESCI 与 SDGs 成果，已修正）。
